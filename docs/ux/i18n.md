# Localisation of the web UI

Design 12.4 (decided 2026-11-07, provisional). This page says how the web UI is localised and
how to add text or a language.

## How it works

- **FormatJS (`react-intl`) with ICU MessageFormat.** Every UI string is a message in a
  catalogue: `web/src/locales/en.json` (the source) and `web/src/locales/et.json` (Estonian).
  Keys name the screen and the meaning (`files.empty.title`, `share.link.turnOff.title`).
- **Code** uses `t('key', values)` for text and `tr('key', { b: (c) => <strong>{c}</strong> })`
  for text with elements in it (both from `web/src/i18n`). `MessageKey` is the type of every key
  of `en.json`, so a wrong key does not compile. Plurals, choices and cases are in the message,
  never built by string concatenation: `{n, plural, one {# file} other {# files}}`,
  `{role, select, admin {an admin} other {a member}}`.
- **Dates, times, numbers and sizes** use `Intl` with the locale of the UI
  (`web/src/components/format.ts`: `formatDate`, `formatWhen`, `formatBytes`, `formatNumber`).
  The units and the words around them ("Yesterday at {time}") are messages.
- **Locale choice:** the user's preference (`getMe` returns `preferences.locale`;
  `updateMyPreferences` sets it), then the browser's languages, then English. The first tag
  with a catalogue wins, and its full tag stays the `Intl` locale (English in a British browser
  writes British dates). The last choice is kept in the browser (`ruum.locale`), so the sign-in
  page speaks it too. The Account page has the picker ("Same as the browser" clears it).
- **API errors** keep their stable `code`; the UI shows `error.<code>` from the catalogue and
  falls back to the server's English `message` for a code it does not know
  (`web/src/api/errors.ts`).
- **Pseudo-locale `en-XA`:** every letter accented, every vowel doubled (about 40% longer), each
  message in brackets. It is made from `en.json` at run time (`web/src/i18n/pseudo.ts`). The
  browser tests (`web/e2e/i18n.e2e.ts`) and the visual tests (`web/e2e/visual.e2e.ts`, the
  "pseudo-locale" pass) run the main screens in it and fail on English text of the catalogue;
  the flow tests (`web/src/test/flows/i18n.test.tsx`) fail on any plain English word that is
  not test data.
- **Lint:** `npm run lint` fails on literal UI text in components (design-system.md, 6.3).
- **Right to left:** `<html dir>` follows the locale; CSS uses logical properties.

## Adding text

1. Add the message to `en.json` and the translation to every other catalogue (the catalogue
   test fails when a key is missing, an argument differs or a plural form is missing).
2. Add its context to `context/en.json` (the context test fails without it).
3. Use `t()` or `tr()` in the code.
4. The copywriter checks the text against the voice (`copy.md`, section 1) and the terms
   (`glossary.md`).
5. Translate it (see "The translation pipeline") and mark it:
   `node scripts/check-translations.mjs --mark machine <tag> <key>`.

## Context for translators

Design 12.4.1: every message has a description for the translator. It is in a sidecar file,
`web/src/locales/context/en.json`, one entry per key of `en.json`:

```json
"files.empty.text": {
  "description": "Files page: ... Empty folder text, for people who can add files. Friendly.",
  "tone": "playful",
  "maxLength": 80
}
```

- **description**: where the message is shown, what it means, what each placeholder holds, and
  any word that stays as it is. The field has FormatJS's name, so the file merges into FormatJS's
  extracted format (`{ id: { defaultMessage, description } }`) when a tool needs it.
- **tone**: `playful`, `neutral` or `calm`, the three registers of the voice (`copy.md`, section 1).
- **maxLength**: the longest the rendered text should be, in characters, with typical values in
  the placeholders. The visual tests check the real fit; the budget tells the translator how much
  room there is.

`src/i18n/context.test.ts` fails when a message has no entry, an entry has no message, a tone is
not one of the three, or the English text is longer than its own budget (each plural or select
counts its longest branch, an argument counts 8 characters).

**Why a sidecar file, not FormatJS descriptions in `en.json`** (copywriter, 2026-11-08,
`provisional`): `en.json` stays a flat map of key to ICU message, the same shape as every
translation. The loader, the `MessageKey` type, the pseudo-locale, the catalogue test, the browser
tests and Weblate's plain JSON format read it as it is, and the app bundles only the messages, not
200 KB of notes. The cost is a second file to keep in step; the context test keeps it in step. The
approved terms are in `glossary.md`.

## Adding a language

1. Add `web/src/locales/<tag>.json` with `@metadata` (`locale`, `source: "en"`,
   `translation: "machine"` until a person checks it, then `"human"`).
2. Add the tag and the language's own name to `LANGUAGES` in `web/src/i18n/config.ts`.
3. Write its style guide, `docs/ux/style-guides/<tag>.md` (like `et.md`), and add a column with
   the language's English name ("German") to the term tables of `glossary.md`, with stems for the
   check script.
4. Translate every message and mark it (`--mark machine <tag> --all`).

## The translation pipeline

Design 12.4.1. Step 1 to 3 run today; the reviewer agent (step 4), the screenshots per message,
the translation memory and Weblate (step 5) are still to come.

1. **Changed messages.** `node scripts/check-translations.mjs --changed` lists, per language,
   the messages that have no translation or whose English changed after the translation. Each
   message has a status in the catalogue metadata (`@metadata.status`): `<state>:<hash>`, where
   the state is `machine` (an agent translated it) or `agent-reviewed` (a reviewer agent checked
   it), and the hash is the start of the SHA-256 of the English message it was made from.
2. **Translate** with the context of the message (`context/en.json`: description, tone, length
   budget), the approved terms (`glossary.md`, the column of the language), the style guide of the
   language (`style-guides/<tag>.md`) and the messages around it (keys of the same screen). Then
   mark it: `node scripts/check-translations.mjs --mark machine <tag> <key>...` (or `--stale`
   for every changed message). A reviewer marks `agent-reviewed` the same way.
3. **Automatic checks**: `node scripts/check-translations.mjs`, part of `npm run lint`. It fails
   on invalid ICU, a missing or extra key, other placeholders, select keys or tags than the
   English, a plural without a CLDR category of the language, an English glossary term without
   its approved translation (the stems in the glossary column), a do-not-translate word that is
   gone, untranslated text (the same as English, or English words such as "the" or "your"), and a
   missing or old status. It warns when a translation is longer than its length budget
   (`--verbose` lists them); the visual tests check the real fit. A message that is the same as
   English on purpose ("Video") is listed in `@metadata.sameAsSource`.
   `scripts/check-translations.test.mjs` shows that each rule catches what it is for.

## Estonian

`et.json` was translated anew on 2026-11-08 by a translator agent with the context file, the
glossary and the style guide (`style-guides/et.md`: informal "sina", the playful and calm voice,
punctuation, numbers and dates, gender-neutral wording). Every message is `machine`; Estonian is
"beta" until a reviewer agent marks every message `agent-reviewed` (design 12.4.1, steps 4 and 6).
The metadata keeps `translation: "machine"` until a person checks it. Rules the translation
follows: a placeholder stands after a noun that carries the case ("kausta {folder}", "ruumis
{space}") or after a colon, so it never needs an ending; numbers take the partitive singular
("3 faili"); "space" is "ruum", so the product name is written only where it is clearly the product
(style guide, section 2).

## Case and terms (UX panel, 2026-11-07)

- Code never changes the case of a message. A text that sits inside a sentence has its own key
  with the case it needs there: `format.when.*.inline` ("yesterday at 2:00 PM"), `role.*.inline`
  ("can edit"), `memberRole.*.inline` ("admin"), `diff.plugin.*.inline`. `npm run lint` refuses
  `toLowerCase` and `toUpperCase` in screens and `src/ui` (rule 6 of `scripts/check-ui-rules.mjs`);
  a use on data that people do not read as a sentence carries `// i18n-ignore: <reason>`.
- A fallback noun phrase never goes into a slot that needs a case form: the message has a
  `select` for the case without the value (`agent.summary` `someFolder`, `trash.restored`
  `hasFolder`, `consent.back.*` `hasGood`).
- Estonian keeps "ruum" for a space. The product name is not written in running Estonian text, and
  labels that could read as "of the space" say what they are ("Kasutajaliidese keel",
  "salvestusruum"); the brand link is named "Ruum, failid" (docs/ux/decisions.md, round 3, D1).
- Separators between facts are "·" in the catalogue, never a hyphen; sizes keep a non-breaking
  space between number and unit.
