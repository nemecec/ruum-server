# Localisation of the web UI

Design 12.4 (decided 2026-11-07, provisional). This page says how the web UI is localised and
how to add text or a language.

## How it works

- **FormatJS (`react-intl`) with ICU MessageFormat.** Every UI string is a message in a
  catalogue: `web/src/locales/en.json` (the source) and `web/src/locales/et.json` (Estonian).
  Keys name the screen and the meaning (`files.empty.title`, `share.link.turnOff.title`).
- **Code** uses `t('key', values)` for text and `tr('key', { b: (c) => <strong>{c}</strong> })`
  for text with elements in it (both from `web/src/i18n`). `MessageKey` is the type of every key
  of `en.json`, so a wrong key does not compile. Plurals, choices and cases are in the message,
  never built by string concatenation: `{n, plural, one {# file} other {# files}}`,
  `{role, select, admin {an admin} other {a member}}`.
- **Dates, times, numbers and sizes** use `Intl` with the locale of the UI
  (`web/src/components/format.ts`: `formatDate`, `formatWhen`, `formatBytes`, `formatNumber`).
  The units and the words around them ("Yesterday at {time}") are messages.
- **Locale choice:** the user's preference (`getMe` returns `preferences.locale`;
  `updateMyPreferences` sets it), then the browser's languages, then English. The first tag
  with a catalogue wins, and its full tag stays the `Intl` locale (English in a British browser
  writes British dates). The last choice is kept in the browser (`ruum.locale`), so the sign-in
  page speaks it too. The Account page has the picker ("Same as the browser" clears it).
- **API errors** keep their stable `code`; the UI shows `error.<code>` from the catalogue and
  falls back to the server's English `message` for a code it does not know
  (`web/src/api/errors.ts`).
- **Pseudo-locale `en-XA`:** every letter accented, every vowel doubled (about 40% longer), each
  message in brackets. It is made from `en.json` at run time (`web/src/i18n/pseudo.ts`). The
  browser tests (`web/e2e/i18n.e2e.ts`) and the visual tests (`web/e2e/visual.e2e.ts`, the
  "pseudo-locale" pass) run the main screens in it and fail on English text of the catalogue;
  the flow tests (`web/src/test/flows/i18n.test.tsx`) fail on any plain English word that is
  not test data.
- **Lint:** `npm run lint` fails on literal UI text in components (design-system.md, 6.3).
- **Right to left:** `<html dir>` follows the locale; CSS uses logical properties.

## Adding text

1. Add the message to `en.json` and the translation to every other catalogue (the catalogue
   test fails when a key is missing, an argument differs or a plural form is missing).
2. Use `t()` or `tr()` in the code.

## Adding a language

1. Add `web/src/locales/<tag>.json` with `@metadata` (`locale`, `source: "en"`,
   `translation: "machine"` until a person checks it, then `"human"`).
2. Add the tag and the language's own name to `LANGUAGES` in `web/src/i18n/config.ts`.

## Estonian

`et.json` is machine translated (an agent translated it, a second agent pass checked the grammar,
the plural forms and the case forms around placeholders) and is marked so in its metadata. Rules
the translation follows: a placeholder stands after a noun that carries the case ("kausta
{folder}", "ruumis {space}") or after a colon, so it never needs an ending; numbers take the
partitive singular ("3 faili"); "space" is "ruum". A person should check it before it is marked
`human`.

## Case and terms (UX panel, 2026-11-07)

- Code never changes the case of a message. A text that sits inside a sentence has its own key
  with the case it needs there: `format.when.*.inline` ("yesterday at 2:00 PM"), `role.*.inline`
  ("can edit"), `memberRole.*.inline` ("admin"), `diff.plugin.*.inline`. `npm run lint` refuses
  `toLowerCase` and `toUpperCase` in screens and `src/ui` (rule 6 of `scripts/check-ui-rules.mjs`);
  a use on data that people do not read as a sentence carries `// i18n-ignore: <reason>`.
- A fallback noun phrase never goes into a slot that needs a case form: the message has a
  `select` for the case without the value (`agent.summary` `someFolder`, `trash.restored`
  `hasFolder`, `consent.back.*` `hasGood`).
- Estonian keeps "ruum" for a space. The product name is not written in running Estonian text, and
  labels that could read as "of the space" say what they are ("Kasutajaliidese keel",
  "salvestusruum"); the brand link is named "Ruum, failid" (docs/ux/decisions.md, round 3, D1).
- Separators between facts are "·" in the catalogue, never a hyphen; sizes keep a non-breaking
  space between number and unit.
