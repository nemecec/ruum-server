This is the digest of design section 18.9 for a person who has a few minutes. Agents did all the

## What step 1 built

Ruum runs on the laptop stack (Postgres, SpiceDB, Garage, Zitadel, NATS, OpenBao, Mailpit, Caddy).

- **Files and versions.** Folders, files, chunked upload, versions with compare and restore,
  trash, tags, search, a journal of every change.
- **Sharing.** Roles `view < comment < edit < manage`, grants to people and to emails, share
  links with a password and an end date, team spaces with members, guests and invitations.
- **Agents.** Agents with their own keys and scopes, OAuth consent, an MCP server (48 tools),
  agent activity and "undo what this agent did".
- **Other ways in.** A CLI (`ruum`), WebDAV for Finder and Windows (on its own host), and the
  web UI (React).
- **Tests.** The tenant isolation suite, the permission matrix, the trashed file suite, property
  tests, a mutation check, browser tests against the real server, visual and accessibility tests.

## Risks

- **Email grants do not bind** to a person who already has an account, and an email grant that
  binds at sign-in does not make the person a guest. Agents and guests who share by email hit
  this (C-12). The web UI works around it for members.
- **The Member role means "manage everything"** in a team space. A careful admin cannot give a
  member less. Only the Guest role limits access per folder.
- **No share emails.** `addGrant` sends no mail; the invitation email leads with the space and
  names no role or end date (C-13).
- **Sign-ins are not in the activity log** (C-14).
- **Agents and names.** Journal entries and versions show agent IDs, not names (C-7), so an agent
  can undo the wrong agent's work when there are two.
- **SpiceDB freshness** outside a request (spawned tasks, the outbox, `seed-dev`) reads at the
  process token. One suite check failed once under heavy load (`401` instead of `404`).
- **Not proven outside this laptop.** CI has never run on GitHub; visual snapshots exist only
  for macOS.
