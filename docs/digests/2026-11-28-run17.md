- **T-82, T-83, T-88: the nightly mutation check in shards** (`ci/t-82`, 1 commit). The
  mutation script has a shard table by name prefix (7 shards: databases, apps, dbengine with
  gateway and egress, runtime, telemetry, core, and a catch-all `rest`, so a new prefix cannot
  drop out). `nightly.yml` runs one job per shard, each with a 300-minute limit and
  `fail-fast: false`; strict mode is unchanged. The nightly job now has the musl target, the
  `ruum_gateway` role and pg_dump 17 that `ci.yml` has: the scheduled nightly on `main` had
  failed its baseline since I6-20 for that reason. T-83: `CI=` (set, empty) is treated as set.
  T-88 (test support only): the gateway test world's `Instances::close` waits for its tasks and
  their sockets, which removes the cold-start 502 flake. No product code changed.
- **B-1d: database bindings of web apps** (`s3/b-1d`, 3 commits; no migration, no contract
  change). A live database binding gets an app role of the data cluster; a draft preview gets a
  masked branch per draft label (made with the deployer's right, B1D-D1) with its own role; an
  ended preview trashes its branch when no active row uses it. `AppService::binding_env_for_start`
  hands out `RUUM_BINDING_<NAME>` connection URLs with a password that lives 24 hours (B1D-D3);
  the start stage does not call it yet, because no card builds node22 deployments (W-2n,
  P-120). The engine checks a tenant's share of the cluster's app connection budget
  (`RUUM_DATA_APP_TENANT_SHARE`, default a tenth of the budget, B1D-D2); the laptop gets 50 from
  `scripts/dev.sh env`. The tenant cap holds across replicas (an advisory lock, S-87). The data
  cluster set-up grants `SET` on `temp_file_limit` to `ruum_dbhost` (D5-3). Closed: D5-3, D5-8,
  D5-9, S-87 and the B-1d part of L1-10. Its own rows: `docs/backlog/2026-11-27-b1d.md`. New
  optional env names: `RUUM_DATA_APP_HOST`, `RUUM_DATA_APP_PORT`, `RUUM_DATA_APP_TENANT_SHARE`,
  `RUUM_APP_DB_SSLMODE`, `RUUM_APP_DB_BRANCH_WAIT_SECS`. 8 new mutations. No new dependency.
