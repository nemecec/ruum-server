## What changed on `main`

Nine branches were rebased onto `main`, checked on the build server, pushed and checked in
GitHub CI, then fast-forwarded, in this order. The history is linear: no merge
commit, no co-author line.

- **`f/content-role`** (decision 0003-1): team members get a content role (view, comment, edit,
  manage; default manage) on the team tree. Accepting an invitation never lowers it.
- **`f/email-grants`** (0003-2, 0003-3): an email grant binds to the account at sign-in with
  the verified email. Share and invitation emails go through a mail outbox.
- **`f/audit-mcp`** (0003-4, 0003-7, 0003-8): sign-ins and credential use are in the audit log.
  MCP gets search by type, batch move and batch tag, and better tool texts. The benchmark has a
  `safe_stop` outcome and harm checks.
- **`s2/spike`**: spike S-1 (see below) and decision 0004-34.
- **`s2/q-0`, `s2/p-1`, `s2/e-1`, `s2/i-1`**: the first step 2 cards. They add the privacy border
  (markers, pseudonyms), the provider trait with its conformance suite, the new crate
  `ruum-dbengine` (engine trait, SQLite memory engine) and the data cluster `postgres-data`.
  No database operation is built yet.
- **`w/design-system`**: design tokens, a component library (`web/src/ui`) with a catalogue and
  lint rules, and every screen on it. The UI is localised (English, Estonian, pseudo-locale)
  and the user's language is stored (`updateMyPreferences`). This branch also has the UX panel
  fixes and the web UI of decision 0003 items 1 to 4 and 7.

Fixes at the integration: four migrations were renumbered, because three branches each took 0005
(the SQL did not change). The files are now `0005` content role, `0006` email grants, `0007`
session tenants, `0008` type index and `0009` user locale. The generated files and the
permission matrix were regenerated. Details are in [STATUS.md](../STATUS.md).

New dependencies: `rusqlite` (E-1). In the web UI: `react-intl`,
`@formatjs/icu-messageformat-parser`, Style Dictionary, stylelint and Ladle.

## Step 2 spike S-1

**Passed: 225 checks, 0 failed** (PostgreSQL 17.11, build server). All six points hold:

1. No database role reaches another role.
2. Masked reads see pseudonyms in every clause, and never the base tables, the key or the stats.
3. The pseudonym function runs only from a view.
4. `masked_write` writes only plain columns.
5. `SET LOCAL` and `DISCARD ALL` leave no session setting.
6. The SQL and the Rust pseudonyms agree on 29 values.

The role kinds of `database_roles` are now frozen. The spike also found six gaps in how the
model is built. Decision 0004-34 (a) to (g) fixes each of them, for example: transaction control
statements are refused, a role's own settings are reset before use, and each type gets its own
pseudonym function with fixed settings. Card C-1 takes one contract text change from (d).
