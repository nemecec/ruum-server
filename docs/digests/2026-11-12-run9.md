## Risks

- **First deploy with O-25 is not zero-downtime.** The edge changes from a Deployment to a
  DaemonSet (a short gap), and certificates are issued once more into the new storage.
- **Rolling deploys and new event types (P-57).** This run adds `database.approval_decided` and
  `app.settings_changed`. During a rollout an old pod's changes feed fails on an unknown type.
  Staging has no real users, so this is acceptable once; the journal fix needs two releases.
- **Drain race (O-30):** a POST at the moment a server pod drains can get a 502.
- **TLS keys in etcd (S-40):** confirm Talos encrypts Secrets at rest on staging.
- **The Postgres permission matrix is slow** (40 to 70 minutes; T-37), and the build server's data
  cluster (768 MiB) is OOM-killed when several suites run at once (B-29); this run saw both.
- **Step 3 security is still mostly on paper**: R-1's driver is in-memory, the gateway is a spike.

## What the orchestrator must do to deploy

1. Push `main` (after gitleaks on `origin/main..main`).
2. **Apply the platform chart first** (`deploy/staging/k8s/apply.sh`, admin rights): the edge
   ServiceAccount and its Role on Secrets and Leases in `edge`, the deployer's rights on
   DaemonSets and Jobs, and the network policy that lets `app: ruum-migrate` pods reach Postgres.
   `deploy-chart.sh` stops with "apply the platform first" if the deployer cannot create Jobs, but
   it does not check the edge ServiceAccount or the policy.
3. Then `deploy.sh` as usual. Its order is now: the migration Job (`ruum-migrate-<sha12>-<time>`,
   `args: [migrate]`, `DATABASE_URL` only, backoff 0) and only after it succeeds the rolling
   update (`helm upgrade`). This run has **no new migration**, so the Job applies nothing.
4. **No new secret.** One new optional server setting: `RUUM_SHUTDOWN_GRACE_SECONDS` (the chart
   sets 35); the chart also sets `RUUM_MIGRATE=false`.
5. A rollback with `deploy.sh --rollback` to a commit before O-25 is refused by design; roll back
   only to O-25 or later.
6. Read `review-o25.md` N-1 (502 during the drain) and N-9 (node drains and the edge) before the
   first rolling deploy.
