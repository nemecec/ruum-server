# Digest run 12 (2026-11-17 to 11-18): step 3 wave 4 (the gateway to sandboxes, the builder) and seven follow-ups

Short report for the person (design 18.9). This run built two step 3 cards, the gateway in front
of app sandboxes (G-1b) and the node22 builder (R-2b), and five follow-up cards: the three Kimi
findings of run 11 (K11), the last FU-1 item, unknown journal event types during rolling deploys
(P-57), the storage quota and garbage collection of static sites (W2S-1), and the telemetry
privacy core that was held back in run 11 (O-1a). All seven are merged. The gateway proxy, the
builder and the telemetry core are not wired into the running server yet (I-4, O-1b). Each panel
decision is `provisional`; you can veto any part. `main` is not pushed: the orchestrator pushes
and deploys.

## What changed on `main`

Seven branches were rebased onto `main` `1d0326f` in one stack, each tip checked on the build
server, pushed as `integ12/...`, green in GitHub CI, then fast-forwarded in this order
(`1d0326f..f33c65a`), plus one integrator commit that moves three stale mutations to the FU-1
code (T-57) and this documentation commit. The history is linear: no merge commit, no
co-author line.

- **K11: the three Kimi findings of run 11.** The egress proxy charges its rate at accept for
  every connection, so a flood of bad requests is closed cheaply and logged as samples. The log
  redactor checks each line against the lines it already let out, so a secret split over two
  lines is hidden. The Docker driver forgets ended instances under caps on count and log bytes;
  the review fix takes from the tenant with the largest share first, so one tenant cannot push out
  another tenant's logs.
- **FU-1 (run 12): masked database copies.** An index of a masked table on a range type whose
  functions are the tenant's code now refuses the copy (Postgres would call that code on rows in
  clear). This closes the last open path of the FU-1 reviews; the rest of FU-1 (catalog labels,
  `current_setting` revoked, the views and statistics of masked copies, names only where the
  contract types a person, untrusted marks) came with the branch.
- **P-57: unknown journal event types.** During a rolling deploy an old server can read an event
  type that the new one wrote. Readers now pass such an entry on with its envelope and empty
  `data`, instead of failing the feed. The design (12.7) now says that a release that writes a
  new type ships only after the release before it reads unknown types.
- **W2S-1: static sites count against the storage quota**, checked before the deploy is accepted
  and again before files are stored; a garbage collection frees site files that no deployment can
  serve, with a guard for the rolling upgrade. No migration.
- **O-1a: the telemetry privacy core** (`ruum-core` `telemetry/`): field classes, the deny list,
  the secret matcher (also percent-encoded, JSON-escaped and base64 forms), pseudonyms for
  personal values, a byte cap that also bounds the output, and the privacy suite. The run 12 work
  closed Kimi's K3 and K4 from run 11 and the five findings of Kimi's run 12 review.
- **G-1b: the gateway in front of sandboxes.** The gateway asks the core where an app's sandbox
  runs, wakes it from zero (a request waits up to about 5 s, then gets a "starting" page), proxies
  HTTP and WebSockets after the access check, rechecks each WebSocket every second and closes it
  when the same visitor no longer passes, and limits held requests and sockets per deployment,
  app, tenant and in total. Until I-4 every sandbox request answers `502`.
- **R-2b: the node22 builder.** A build runs in a sandbox job of its own (the R-2a hardening, one
  internal network with only the egress proxy and `registry.npmjs.org`), and the image is
  assembled without a Docker daemon and pushed once by digest to the app's own repository. The
  review fixes refuse cut or padded build output, keep registry credentials to the registry's own
  origin, check upload addresses after normalization, cap every body read, bound deep paths, and
  clean up a cancelled build.

New dependency: `hyper-util` 0.1.21 (already in the tree through axum and reqwest; G-1b).
New gateway settings with defaults: `RUUM_GATEWAY_HOLD_PER_TENANT` (256) and
`RUUM_GATEWAY_WS_PER_TENANT` (2048).

## Risks

- **Five of seven cards have no finished Kimi verdict on their final code** (S-63). Only FU-1
  has an APPROVE. The code with the most new attack surface (the gateway proxy G-1b, the builder
  R-2b, the driver fairness of K11) is not wired yet, so the risk lands with I-4, which must not
  start before the Kimi runs.
- P-57 and W2S-1 run on staging with this deploy. W2S-1 starts a garbage collection of static
  site files; a narrow rolling-upgrade window remains (P-87 A), and a tenant whose storage is
  full cannot roll back a site (P-87 B).
- FU-1 changes the data cluster set-up (`current_setting` revoked from `PUBLIC`, expand then
  contract). Staging has no data cluster, so nothing changes there now; the two-step order
  matters when one is added (below).
- Short secrets (1 to 3 bytes) are not found inside longer words in telemetry (S-64); O-1a is
  not wired yet (O-1b).
- Four tenants at their gateway shares fill a global cap (S-65).
- A rebuild check of the lens (`setup.rs`) has no test of its own after FU-1 (T-57); the masked
  copy's own check is tested and guarded by a mutation.
- Build server: queued checks need a fresh data cluster each (B-39) and one key per worktree or
  a copy without old file times (B-41); timing tests fail under load (T-54).
