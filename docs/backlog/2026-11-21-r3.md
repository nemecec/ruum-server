# Backlog 2026-11-21, card R-3 (step 3 wave 6)

The impl notes are `ruum-server-wt/panel/impl-r3.md`. The IDs start with `R3-`, so they do not
clash with the numbering of the run's integrator. Kinds, efforts and handlings are as in
`docs/backlog/2026-11-08.md`. All decisions here are `provisional` (design 18.9).

| R3-3 | question | `delegated-token.schema.json` says `on_behalf_of` is "the platform user ID", format `uuid`; card R-3 says the runtime API never sees a platform user ID. The runtime API puts a **sealed subject** there: the platform user ID encrypted with a key only the core has (one AES-256 block, the key derived from the tenant's pseudonym key and the app), in UUID form. It fits the schema's format, and neither the runtime API nor the app can read the user ID (a JWT is readable by the app). Proposal: change the description to "an opaque UUID that names the user to the platform". | `crates/ruum-core/src/apps/runtime_api.rs` "Delegated tokens and the user" | r3 | S | **panel**: description change of the schema (no shape change). |
