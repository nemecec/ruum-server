| I620-2 | security | **Node-to-node traffic is not encrypted on staging.** The supervisor's launch channel is plain HTTP (decision 0006 I point 4); the chart refuses `runtime.kubernetes` without `runtime.nodeNetworkEncrypted=true` and the server refuses it without `RUUM_KUBE_SUPERVISOR_NETWORK=encrypted`. | design "Transport" | M | **O card**: Talos KubeSpan (or the CNI's WireGuard) on every node, checked with `talosctl get kubespanpeerstatuses`; or TLS on the supervisor listener with a certificate the supervisor pins (then the setting can say `tls`). |

| I620-4 | gap | **Redactor memory is not budgeted.** The live log budget (S-91) counts ring lines; each instance's two redactors (driver and its automaton) are bounded by the secret limits (256 values, 256 KiB) but not counted together. | Kimi design review finding 11 | S | **card**: count the redactors' automaton size per instance and refuse a start (or share automatons) past a process budget. |
| I620-5 | gap | **The record key has no rotation.** One key id is read; the seal format carries the key id. AES-GCM with random nonces stays safe far below 2^32 seals per key. | `src/kube/seal.rs` | S | **card**: a second key read for one release (`RUUM_KUBE_RECORD_KEY_FILE` plus an old key file), records re-sealed by the sweep, then the old key removed. |
| I620-6 | decision | **A hostile app can keep its own value in the pod's termination message** (4 KiB in the pod status, readable by the runtime identity and admins) by writing `/dev/termination-log` and ignoring `SIGTERM` until the kubelet's `SIGKILL`; the supervisor empties the file before and after the app otherwise. The app holds its values anyway (rule 7 "honestly"), so nothing new leaks to another tenant. Provisional: accepted. | design "Known limits"; Kimi design review finding 8 | S | **person** (optional): confirm, or ask for a card that keeps the file unwritable (needs a different user for the app than for the supervisor, which restricted Pod Security does not allow today). |
| I620-7 | gap | **The Docker driver's supervisor is not wired in the server.** `DockerConfig::supervisor` exists and the Docker tests use it; the server's Docker wiring is card I-4's (`RUUM_SUPERVISOR_BIN` or a binary in the server image). | `crates/ruum-runtime/README.md` "Settings" | S | **brief** for I-4: a setting for the binary path on the engine's host. |
| I620-9 | security | **The anti-rollback state of a seal is per server process.** The generation high-water mark and the launched list live in each process and in the attacker-writable record; a seal put back before the launch can make another (or a restarted) replica launch the same pod again within 120 s of its start, which returns that pod's previous values. Needs a holder of the runtime token and the pod's own app together. | Kimi code review of I6-20, finding 2 (`panel/kimi-i620-code.md`) | M | **card**: keep the generation and the launched pod uids in the platform database (compare-and-swap), the ConfigMap only the encrypted cache. |
| I620-10 | gap | **A cluster-wide default PriorityClass would refuse every sandbox pod**: the read-back allows only `priority: 0` and no `priorityClassName`. Staging has none. | Kimi code review of I6-20, finding 6 | S | **brief**: set a platform PriorityClass on the pods and verify it. |
| I620-11 | gap | **Docker: a scaled-to-zero instance's ring stays in the live budget** (the Kubernetes driver moves it to the ended cap). Bounded (the tenant's share, the sweep), and Docker is the laptop's and CI's. | Kimi code review of I6-20, finding 4 | S | **brief**: a parked state in the Docker driver as in the Kubernetes driver. |
