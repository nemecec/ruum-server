# Backlog 2026-11-17, card R-2a review fixes

Items left by the review fixes of card R-2a (the Docker driver with runsc, the hostile sandbox
suite, S-36), after the review (`ruum-server-wt/panel/review-r2a.md`) and Kimi's review
(`review-r2a-kimi.md`). The fixes are in `review-r2a-fix.md`. The IDs are `R2A-n` so that they
do not collide with the run backlogs. Kinds, efforts (S, M, L) and handlings are as in
`docs/backlog/2026-11-08.md`. All decisions here are `provisional` (design 18.9).

| ID | Kind | Item | Evidence | Effort | Handling |
|---|---|---|---|---|---|
| R2A-1 | gap | Full reconciliation of the Docker driver at `connect` after a server restart. The driver keeps instances and networks in memory; a new start adopts the network of an earlier run (labels match, read-back passes), but the containers of that run (`ruum.managed=ruum-runtime`) keep running unmanaged, their usage records are lost, and a network no new start adopts stays, with its egress registration. Decide: adopt the containers (instance IDs are in the label `ruum.instance`) or remove them, record the usage, and unregister and remove the networks nobody adopts. | review-r2a change 2 | M | **pipeline**, R-2b, I-4 or I-6 |
| R2A-2 | question | runsc without `--oci-seccomp`: Docker's seccomp profile is not applied inside gVisor, so `unshare -U` works there (gVisor's own kernel; no host user namespace). Decision 0006 G point 5 wants user namespaces under runsc for Railpack with rootless BuildKit, which the flag would forbid. The driver logs a warning at connect when the engine's `runsc` has no `--oci-seccomp`. Decide per pool (apps, builds) and record it in decision 0006 G with the runsc cold start numbers. | Kimi review of R-2a, finding 2; review-r2a note 1 | S | **panel**, I-6 |
| R2A-3 | gap | Secret values are in the container's `Config.Env`, which `GET /containers/{name}/json` returns. I-4's socket proxy must give the engine API to the server only (whoever calls it can also run code in every container). A delivery that keeps secrets out of the container config (a file on a tmpfs, read by an entrypoint) would change the app contract (apps read env) and is a design question. | Kimi review of R-2a, finding 3; review-r2a note 11 | M | **panel**, I-4 |
| R2A-4 | gap | Usage is recorded only when a run ends (no interim records; nothing after a crash); `memory_bytes` is the limit. | review-r2a note 2 | S | **pipeline**, R-5 / metering |
| R2A-5 | gap | Instances are never removed from the driver's map: each exited job or stopped service keeps its log ring (up to 4 MiB). Needs an eviction policy (after the log shipper read the lines). **Done** (card K11, Kimi review of run 11, finding 3): ended instances go after a retention (shorter once their logs were read to the end), with caps on ended instances, their log bytes and all instances (`crates/ruum-runtime/README.md`). | review-r2a note 3 | S | **pipeline**, R-2b or R-5 |
| R2A-6 | improvement | All network work of all tenants waits on one lock (`networks`), held across network create, attach, inspect and the egress HTTP call (10 s timeout). A lock per network name would let other tenants' first starts go on. | review-r2a note 5 | S | **pipeline**, R-2b |
| R2A-7 | gap | The driver does not check the shared containers' hardening (`ip_forward=0`, `forwarding=0`). I-4 starts them so; the driver could read it back at `connect`. | review-r2a note 12 | S | **pipeline**, I-4 |
| R2A-8 | gap | Fault injection for the Docker API (a refused kill or stop, an error on the wait stream): the driver now escalates (SIGKILL each second, removal by force after 10 s, a second wait while the container runs, bounded joins in `stop` and `wake`), but no test injects the engine errors. Needs a proxy in front of the engine socket in the test harness that fails chosen calls. | Kimi review of R-2a, finding 4 | M | **pipeline**, I-4 (with the socket proxy) |
