## Provisional decisions

| ID | Decision | Why | Revisit |
|---|---|---|---|
| I613-D1 | The build pod's input and output go through a **build channel** of ruum-server (TLS 1.3 with the supervisor listener's certificate, pinned by the pod's fixed `node -e` program; a 256-bit token per build; the pod's address; once each; the output cap), not through `pods/attach` or a ConfigMap. | No exec or attach right for the server (rbac-check), ConfigMaps hold 1 MiB, pod logs are cut by the kubelet. The channel reuses the listener caps of S-89. | When the supervisor can run builds too. |
| I613-D2 | The registry is **zot** (`ghcr.io/project-zot/zot-linux-amd64:v2.1.20`, by digest) with htpasswd users and access rules: `ruum-pull` read, `ruum-push` read and create, no anonymous policy. | `registry:2` with htpasswd gives every user every right; pull-only nodes need per-user rules. One binary, no database. | A new image or a token service. |
| I613-D3 | A publish of a node22 deployment **with bindings** starts no live instance before the switch; without bindings it starts one as the live environment and stops it. | The live credentials of a binding exist only after the switch (`binding_env_for_start` checks the live deployment); the preview passed the start with the same image and manifest. | With W-3b's approvals or a pre-switch credential. |
| I613-D4 | A node22 manifest with `static`, `jobs`, `events`, `apis` or `egress.allow` stays `409 runtime_not_ready` (pointer to the part). | The gateway serves no static files next to a server yet; R-5, R-6 and B-3 are not built; no runtime path narrows the proxy's allow list (the app would get more than it asked for). | With those cards. |
| I613-D5 | The start check: running and **healthy** (the manifest's `health.path`, a probe inside the sandbox) within `health.timeout_seconds` + 30 s counted from the start request, at most 120 s for a preview's stage `start` and at most 60 s for the start before a publish (`Node22Settings::publish_start_wait`; it runs inside the request, whose default timeout is 120 s; review I6-13, 3); then stopped (scale to zero). The check result is one route. | Decision 0006 G point 1 (never probe from the host); the browser check is O-4. | O-4. |
| I613-D6 | A node22 preview holds its deploy slot until its build has read the archive (the build and the wait for a build slot). At most `SERVER_DEPLOYS` (`GLOBAL_DEPLOYS` - 1 = 3) node22 previews hold a slot at the same time in a process; one more gets `409 conflict` with `Retry-After` at once (review I6-13, 1). | The archive is in memory until the build has read it, so the slot must cover it; the slot left over keeps static deployments of every tenant going while builds queue. | A builder that streams the archive from the blob store, or a pool of its own for builds. |
