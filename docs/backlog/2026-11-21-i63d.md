| I63D-1 | gap | The static bucket `ruum-staging-static-768usm` has no nightly copy: `blob-copy` (charts/platform) copies only the blob bucket. The sites can be written again from the deployment archives (their chunks are in the blob bucket), but no tool does it, so a lost static bucket means a redeploy of every app. | `deploy/staging/charts/platform/templates/blob-copy.yaml`; `ruum_core::apps::static_links` | i63d | S | **pipeline**, the next O card: copy the static bucket in the same CronJob (another source, the same crypt remote under its own path), or a rebuild of the sites from the archives. |
| I63D-2 | improvement | The core reads the site index (one S3 `GET`, up to 16 MiB) for each static request of the gateway (`StaticSites::file_link`). Before I6-3D the gateway did the same read with its own key, so the load only moved; indexes never change, so a small bounded cache per deployment in the core would remove most of these reads. | `crates/ruum-core/src/apps/static_site.rs` `file_link` | i63d | S | **pipeline**, with the first load test of static apps. |
| I63D-3 | gap | A rollback to a ruum-server older than I6-3D does not see the sites in the static bucket (it reads the blob bucket), so sites deployed after the upgrade (and every site, once the newer release has deleted the old copies, from one hour after its start) answer `404` until the newer release is back; that release moves the older release's sites over again. Staging serves no static app today, so the cost is small. | `deploy/staging/README.md` "Going back" | i63d | S | **panel**: accept for staging; a release before real users keeps the previous release able to read the static bucket (design 12.7). |
| I63D-4 | improvement | The gateway fetches each link from the public S3 endpoint (Hetzner, 443): the network policy keeps the general "public addresses on 443" rule of I-6. A narrower rule (only the object storage endpoint's addresses) needs FQDN policies or an egress gateway; plain Kubernetes network policies take only address blocks, and the endpoint's addresses can change. | `charts/platform/templates/networkpolicies.yaml` `gateway-egress` | i63d | S | **pipeline**, with S-79 or a later network card. |
