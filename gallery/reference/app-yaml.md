# app.yaml reference

Generated from `contracts/manifests/app.schema.json` by `ruum_core::templates::reference`. Do not edit this file: the test `gallery_reference_is_current` fails when it differs from the schema. To write it again, run that test with `RUUM_WRITE_GALLERY_REFERENCE=1`.

Start every `app.yaml` with this line, so an editor checks the file as you type:

```yaml

```

The manifest of a web app: the file `app.yaml` at the root of a deployment archive (docs/DESIGN.md, sections 9.1 to 9.10; decisions 20 to 26). Each live deployment is a version of the `webapp` node (encoding `app_release_v1`); the manifest travels in the archive, not in the node. The settings that are not in the archive (who may use the app, the telemetry mode, the report widget) are `AppSettings` of openapi.yaml. Binding targets are paths relative to the app node (`../garden.db`) or absolute in the tenant (`/Photos/Garden`) and are resolved to node IDs at deploy time. Step 3 accepts the runtimes `static` and `node22`; `python3.13` comes later in step 3 (decision 20) and fails validation until its card lands; `container` is not accepted in step 3. DRAFT for review (step 3 specify phase, docs/STEP3.md).

`<name>` stands for a key that you choose (a binding, a role, a secret); `[]` for an item of a list.
